计时含义

spmv_avg 是报告里用于比较的主指标。

no-TAPA 的 spmv_avg 来自 host 端包住 run.wait() 的 wall time；xrt_setup、BO setup、H2D/D2H 单独列出。

TAPA 的 spmv_avg 来自 tapa::invoke 返回的 kernel 时间；TAPA runtime 打印的 load/opencl 日志不直接计入这个值。

full-PCG 代理的 pcg_proxy_ms 来自 [timing-ms] kernel=...，包含初始 Cuper packed SpMV 和向量初始化，不能和 single-SpMV 的 spmv_avg 当作完全同口径指标。

新 TAPA full-PCG 的 tapa_pcg_init_ms 和 tapa_pcg_1iter_ms 均来自 [timing-ms] kernel_reported=...；新版 host 同时输出 [pcg-spmv-ms] 和 [pcg-control-ms]，用于区分 SpMV 本身、PCG 非 SpMV 控制和向量更新、controller 外 kernel/runtime 开销。host wall time 另含 xclbin load/runtime 同步开销，不用于总表。

当前 one-shot CuperPcgSpmv demo 的 spmv_avg 来自 [timing-ms]；旧 service 版 timeout 结果只作为历史失败块保留。

大数据 TAPA SpMV 未返回发生在 --spmv-only 路径，不是 host 端 PCG 全流程被砍掉后才进入的路径；本轮表现为 thermal2_n262144 和完整 thermal2 180s 超时。 timed-debug 版 TAPA full-PCG 已能返回到 thermal2_n262144，且 stage counter 有效；完整 thermal2 两种 PCG 口径重测时控制寄存器都保持 0x0 未完成。 旧 PCG SpMV 抽出版 demo 在最小 thermal2_n16 即两次 timeout；当前同名 one-shot demo 已跑完整 thermal2。single SpMV 测试本身未跑 PCG，无 init/1iter 过程；full-PCG 分层重跑日志来自 logs/pcg_breakdown_20260529_hostsplit/。

后续建议

TAPA 路线的 kernel 吞吐很强，优先查 host/cuper_tapa_pcg_main.cpp 里 大 batch 场景的 tapa::invoke 返回路径、buffer size、aligned mmap 生命周期和 TAPA runtime 对大 mmap 的同步行为。 由于卡住发生在 --spmv-only 路径，host 侧 PCG 全流程被砍掉不是主要嫌疑。 当前失败阈值在 N=131,072 与 N=262,144 之间。

当前 TAPA full-PCG demo 已把可返回规模拉到完整 thermal2；新版 host 分层数据显示 raw SpMV 不是当前 1iter 主瓶颈。2026-05-29 PCG 重跑中，完整 thermal2 1iter 的 update_xr=718.41 ms、update_p=598.67 ms、 dot_p_ap=187.24 ms、init_zp=230.74 ms， controller 外开销只有 11.13 ms。下一步优先查 PCG controller 内的 FP64 向量更新、归约和 P/AP 消费路径。

旧 PCG SpMV 抽出版 single SpMV demo 的返回路径问题已经作为历史记录保留： thermal2_n16 已能完成 H2D、Exec 和 D2H，但卡在 ReadFromDevice 后的 Finish 阶段。当前 one-shot demo 已去掉这层 service stop/drain 控制，且已完成 demo-only 上板测试到完整 thermal2。下一步若继续推进，应解释为什么共同成功点仍略慢于标准 TAPA Cuper SpMV。

2026-06-15 Jacobi demo 显示第五主线已从单轮 smoke 扩到完整固定轮数： thermal2_n1024 固定 451 轮，完整 thermal2 固定 24409 轮，均返回并校验通过。 但当前硬件仍不做内部收敛 early-exit，Status=1 只表示到达 MAX_ITERS。如果后续要把它从 debug demo 变成标准主线，需要补两件事： 在硬件侧加入真实 diff/early-exit 或明确保留 fixed-count ABI，并把 Status/Metrics 改为周期性可见，避免完整矩阵长运行时只能等 kernel 结束后判断状态。

no-TAPA 路线已能拉通百万级数据，可作为继续比较 PCG 全流程和端到端预处理开销的稳定基线。 如果只看单次 SpMV kernel，当前 no-TAPA 4ch 大数据吞吐约 0.08 GFLOP/s，和 TAPA 已完成点差距较大。
